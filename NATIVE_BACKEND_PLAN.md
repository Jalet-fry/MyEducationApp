# MyEducationApp: Переход на Нативный Бэкенд (Новая Архитектура)

## 🎯 Цель: Упрощение и реальное выполнение кода
Вместо имитации логики внутри Android-приложения, мы переходим на схему с полноценным бэкендом (Ktor), который исполняет реальный Kotlin/Java код.

---

## 🏗 Новая Архитектура

### 1. Модуль `:shared` (Common Models)
- Содержит только POJO/Data-классы: `Lesson`, `Course`, `Parameter`.
- Независим от Android/Compose. Использует `kotlinx.serialization`.

### 2. Модуль `:server` (Ktor Backend)
- **Engine**: Ktor Server (Netty).
- **Logic**: Каждое практическое занятие — это простая функция (напр., `fun lesson1_1()`).
- **Registry**: Карта соответствия `id -> Function`.
- **Executor**: Перехватывает `System.out` во время выполнения функции и возвращает результат в JSON.

### 3. Модуль `:app` (Android Frontend)
- Отвечает только за UI.
- Получает данные об уроках через API бэкенда.
- Отправляет параметры на бэкенд и выводит полученный лог в "консоль" приложения.

## 🛠 План реализации

1.  **Реорганизация модулей**: (В ПРОЦЕССЕ)
    - [x] Создание `:shared` и перенос моделей.
    - [x] Настройка `:server` с Ktor.
    - [ ] Подключение `:shared` к обоим модулям.

2.  **Реализация логики уроков (Logic)**:
    - Перенос существующего кода из `logic.impl.*` в простые функции внутри `:server`.
    - Пример:
      ```kotlin
      fun runLesson2_1(params: Map<String, Any>) {
          val age = params["age"] as Int
          println("Age is $age")
      }
      ```

3.  **API Эндпоинты**:
    - `GET /lessons` — список всех уроков.
    - `GET /lesson/{id}` — детали конкретного урока.
    - `POST /execute/{id}` — запуск кода с параметрами.

4.  **Скрипты автоматизации**:
    - Обновить `generate_lessons.py` для генерации кода/данных, совместимых с новым бэкендом.

---

## 📂 Новая Структура (Проект)
- `app/` — Android UI (Jetpack Compose).
- `server/` — Ktor Server + Lesson Implementations.
- `shared/` — Common Data Models.
- `kotlin_lessons/`, `java_lessons/` — Исходники (PHP) с Metanit.

---

## 🚀 Преимущества
1. **Простота**: Не нужно городить сложные интерфейсы `LessonBackend` в UI.
2. **Настоящий код**: Мы запускаем реальный JVM-код, а не имитацию.
3. **Масштабируемость**: Легко добавить поддержку Java-уроков, просто вызывая Java-классы из бэкенда.
4. **Удобство отладки**: Бэкенд можно запускать и тестировать отдельно от Android-эмулятора.
