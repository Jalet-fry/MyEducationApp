# Архитектура проекта MyEducationApp

Данный проект представляет собой интерактивное обучающее приложение на базе Jetpack Compose. Его структура разделена на уровни представления (UI), бизнес-логики и обработки данных. Ниже приведено описание каждого файла и его роль в системе.

## 1. Слой UI и Темы (ui/theme)

Эти файлы отвечают за визуальную составляющую и единообразие интерфейса согласно концепции Material Design 3.

* **Color.kt**: Содержит декларативное описание цветовой палитры. Используется для определения базовых цветов приложения.
* **Type.kt**: Определяет типографику (Typography). В нем задаются стили текста для различных категорий (`bodyLarge`, `titleLarge` и т.д.).
* **Theme.kt**: Центральный файл темы. Объединяет цвета и шрифты, реализует поддержку темной и динамической тем через `MyEducationAppTheme`.

## 2. Слой логики (logic)

Этот слой отвечает за выполнение интерактивного контента уроков через систему **Native Backends**.

* **LessonBackend.kt**: Определяет базовый контракт (`LessonBackend`) и реестр (`LessonRegistry`). 
    * `runSafe`: Утилита для выполнения Kotlin-кода с перехватом стандартного вывода (`println`, `print`), что позволяет писать логику уроков на чистом Kotlin.
* **logic/impl/**: Папка для конкретных реализаций логики уроков. Каждый урок (например, `Lesson21Backend`) инкапсулирует алгоритм, который раньше мог быть в PHP.

## 3. Ядро и Модели данных

* **Lesson.kt**: Содержит DTO (Data Transfer Objects) для описания структуры урока: `Lesson`, `LessonSection`, `Parameter`.
* **LessonsRepository.kt**: Отвечает за загрузку данных уроков из `assets`. Поддерживает загрузку как из JSON, так и из специально размеченных `.kt` файлов.
* **SyntaxHighlighter.kt**: Утилита для подсветки синтаксиса Kotlin в блоках кода, использующая цвета, совместимые с темой оформления.

## 4. Реализация и Регистрация

* **ui/lessons/LessonBackends.kt**: Точка регистрации всех бэкендов. Здесь вызывается `LessonRegistry.register()` для каждого реализованного урока.
* **MainActivity.kt**: Главная Activity, управляющая навигацией и отображением экранов. Связывает ввод пользователя (слайдеры, поля) с бэкендами уроков.

## 5. Устаревшие компоненты

* **CodeExecutor.kt**: Динамический интерпретатор. В текущей архитектуре Native Backends он является резервным механизмом и постепенно заменяется прямой реализацией логики на Kotlin для повышения стабильности.

### Резюме по подходу Native Backend
Вместо попыток написать идеальный парсер Kotlin на Android, мы переносим логику каждого сложного урока в отдельный Kotlin-объект. Это гарантирует 100% корректность выполнения, высокую скорость и позволяет использовать все возможности языка (циклы, рекурсию, коллекции) без ограничений интерпретатора.
